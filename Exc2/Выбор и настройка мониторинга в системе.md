# Выбор и настройка мониторинга в системе

## Раздел 1: Мотивация

Мониторинг обеспечивает своевременное выявление и устранение неисправностей, улучшает качество обслуживания и снижает затраты на поддержку. Это способствует:

- Улучшению обнаружения и устранения проблем в реальном времени.
- Повышению удовлетворенности клиентов благодаря стабильной работе системы.
- Оптимизации использования ресурсов команды за счет проактивного реагирования на инциденты.

## Раздел 2: Выбор подхода к мониторингу

### Интернет-магазин (Shop API)
- **Подход:** **Четыре золотых сигнала**
  - **Почему:** Интернет-магазин критичен к латентности и ошибкам, так как это первый контакт клиента с системой. Подход "Четыре золотых сигнала" позволяет комплексно оценивать здоровье системы, включая latency и ошибки, что важно для интерактивных систем.
  - **Латентность:** Response time (latency) для Shop API.
    - **Ярлыки:** endpoint, method
  - **Трафик:** Number of requests (RPS) для Shop API.
    - **Ярлыки:** user_id, endpoint
  - **Ошибки:** Number of HTTP 500 и 200 для Shop API.
    - **Ярлыки:** status_code, endpoint
  - **Насыщенность:** CPU % и Memory Utilisation для Shop API и базы данных.
    - **Ярлыки:** instance_id

### CRM
- **Подход:** **RED (Rate, Errors, Duration)**
  - **Почему:** CRM требует мониторинга RPS и количества ошибок, а также оценки времени отклика для внутреннего использования.
  - **Rate:** Number of requests (RPS) для CRM API.
    - **Ярлыки:** user_id, endpoint
  - **Errors:** Number of HTTP 500 для CRM API.
    - **Ярлыки:** status_code, endpoint
  - **Duration:** Response time (latency) для CRM API.
    - **Ярлыки:** endpoint, method

### MES
- **Подход:** **USE (Utilization, Saturation, Errors)**
  - **Почему:** MES система сфокусирована на эффективности использования и насыщенности ресурсов.
  - **Utilization:** CPU % и Memory Utilisation для MES API.
    - **Ярлыки:** instance_id
  - **Saturation:** Number of simultaneous sessions для MES API.
    - **Ярлыки:** session_type, endpoint
  - **Errors:** Number of HTTP 500 для MES API.
    - **Ярлыки:** status_code, endpoint

### RabbitMQ
- **Подход:** **USE (Utilization, Saturation, Errors)**
  - **Почему:** Важно контролировать ресурсы, задействованные в обработке сообщений, чтобы избежать задержек и потерь.
  - **Utilization:** Процент использования очередей.
    - **Ярлыки:** queue_name, exchange
  - **Saturation:** Messages in flight в RabbitMQ.
    - **Ярлыки:** queue_name
  - **Errors:** Dead-letter-exchange letters в RabbitMQ.
    - **Ярлыки:** queue_name, reason


## Раздел 3: Метрики для отслеживания

1. **Интернет-магазин (Shop API):**
   - **Латентность:** Response time для определения скорости ответа.
   - **Трафик:** RPS для понимания нагрузки.
   - **Ошибки:** HTTP 500 и 200 для выявления сбоев и успехов.
   - **Насыщенность:** CPU % и Memory Utilisation для оценки ресурсов.

2. **CRM:**
   - **Rate:** RPS для отслеживания нагрузки.
   - **Errors:** HTTP 500 для идентификации ошибок.
   - **Duration:** Латентность для анализа времени ответа.

3. **MES:**
   - **Utilization:** CPU % и Memory Utilisation для оценки использования ресурсов.
   - **Saturation:** Одновременные сессии для определения нагрузки.
   - **Errors:** HTTP 500 для мониторинга ошибок.

4. **RabbitMQ:**
   - **Utilization:** Использование очередей для оценки нагрузки.
   - **Saturation:** Messages in flight для контроля за активностью.
   - **Errors:** Dead-letter-exchange letters для выявления проблем с доставкой.
